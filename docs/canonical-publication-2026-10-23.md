# 不可变 buffer 发布复用实验（2026-10-23）

私有候选在 StateStore 已逐字节确认输入等于现有 buffer 后，将该不可变 owner 的
数据交给共享池；共享池仅在长度一致且 data 指针完全相等时省略重复 `memcmp`。
输入 hash 校验、冷读取、不同 buffer 的冲突检测、发布、只读/poison 和 barrier
均保留，没有修改持久化格式或公共 API。产品代码未改，暂不推广此候选。

## 正确性证据与收益边界

基线和候选都通过原共享池、共享快照和扩展 StateStore 集成测试；后者覆盖重复
保存 owner、等内容独立副本、错误 reference hint、全局发布及旧镜像不变。
候选另通过七项原生场景和独立 Raft native reference。

DeepSeek-V4.1-Flash / max 的只读审查指出：扩展集成测试没有强制命中优化分支。
新写入时 StateStore hot cache 与共享池仍可能各自复制一份，只有 StateStore 持有
共享池的同一个 owner、且共享池尚未淘汰它时，才能省略比对。不能用测试结果正确
推断分支实际命中，也不能用这份候选声称已消除两层缓存的副本。

随后增加独立计数回归，通过 `--wrap=memcmp` 和 `-fno-builtin-memcmp` 仅统计
指定指针对与长度。主 agent 实际编译、执行结果如下：

| 场景 | 基线比对次数 | 候选比对次数 |
| --- | ---: | ---: |
| Blob 同一 owner 重复发布 | 1 | 0 |
| Ready 同一 owner 重复发布 | 1 | 0 |
| 相同内容、不同地址 Blob | 1 | 1 |

错误 Blob key、只读 pool 持有 owner、syncfs 故障 poison 后持有 owner 的发布均
继续拒绝。用“应省略比对”要求基线、或用“应执行比对”要求候选时，测试分别
以 `count 1 != 0` / `count 0 != 1` 失败，证明这个回归确实区分了两条路径。
此测试没有测量真实搜索的命中率，也没有新增并发或淘汰压力覆盖。

## 全链路测量

固定 NP3 Raft-library、pages/shared、BFS depth12、seed1、rounds100、same-cpu、
locality none。两版使用同代 O3 full-FP 对象，仅替换 pool 与 StateStore 实现。
基线 SHA `ef808de53b2db36fcf644a2ac4e4ec9231a467702e8bc3f88f191cea95cc75c7`；
候选 SHA `812895ab6ec1c2716cca335a64a7321039387e9b4ec0db868a66e46e884f2865`。

gpunode WSL 两轮反转顺序，秒数为搜索命令加验证之后的延后关闭：

| workers | 基线两次 | 候选两次 | 基线中位数 | 候选中位数 |
| --- | --- | --- | ---: | ---: |
| 1 | 23.9732 / 25.7344 | 25.8714 / 25.7399 | 24.8538 | 25.8056 |
| 12 | 4.2309 / 3.9936 | 4.0252 / 3.9719 | 4.1123 | 3.9985 |

12-worker 中位数低约 2.8%，但两轮分别改善约 4.9% / 0.5%；单-worker 中位数
反而高约 3.8%。样本不足以确认稳定收益或回归，更不能把单-worker 变慢形成的
较大相对倍率当作扩展性优化。暂不合入。

本机另有三轮完成，期间观察到不属于实验的 Pylance 和 Ollama 额外负载，已经
保存干扰记录，不将这些时间用于性能排名。WSL 开始前 guest 空闲检查不等于
Windows 宿主完整空闲证明；宿主计数器探测在本轮计时结束后才运行。

WSL 十次运行（两份参考加八次计时）全部通过 10457 节点、18266 边、18266
尝试边、零重试；下载后逐份重算规范图 SHA 均为
`56ccf7cc9b866e62f6da715136eb596719b3f2b101915e93e4cf0c630217717b`。
参考只独立验证节点/首次发现父边，完整带标签图另行比较；不是通用语义等价证明。
搜索加延后关闭是两个不连续区间，中间验证不计时，不能当作立即关闭或连续端到端。
