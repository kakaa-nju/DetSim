# Worker 缓存容量对照（2026-10-24）

将每 worker 的 StateStore hot cache 从 32 MiB 增至 64 MiB，在这组
12-worker Raft-library 搜索中消除了逐出，却没有可辨认的吞吐收益。
不据此修改默认容量，也不把缓存逐出次数当作线性加速的主要阻碍。

## 范围与方法

沿用[工作量诊断](worker-work-accounting-2026-10-24.md)的 depth16、seed1、
pages/shared、100 rounds 输入。目标是 Raft 库驱动，不是完整 Redis 服务。
Python 仅配置、启动和核对；探索由内置 parallel BFS 完成。
配置包装器只替换 Session 构造中的 hot_cache_mb，并检查参考运行的实际配置。
64 MiB 使用自己的参考运行，不借用 32 MiB 参考作为配置一致性证明。

诊断版用于计数，未插桩 typed-pool 版用于计时。计时仅使用 tracer 的
自动搜索 receipt.seconds，排除准备、串行参考、驱动等待和收尾。
四个计时样本按 32、64、64、32 顺序执行；参考运行不参与中位数。

## 结果

| 未插桩搜索 | 32 MiB | 64 MiB |
| --- | ---: | ---: |
| 第一轮，秒 | 19.973900261 | 20.030906224 |
| 第二轮，秒 | 20.097638896 | 20.035453402 |
| 中位数，秒 | 20.035769579 | 20.030906224 |

差异约 -0.024%，只能称为基本持平。两轮不足以估计小幅收益的置信区间。
这里没有未插桩的 1-worker 容量配对，不能由此重新声称加速比提高。

独立诊断运行的 12-worker 合计：

| 计数 | 32 MiB | 64 MiB |
| --- | ---: | ---: |
| StateStore 逐出调用 | 41841 | 0 |
| 逐出字节 | 784688996 | 0 |
| 页面 save 调用 | 220586 | 217747 |
| StateStore load 请求 | 6349797 | 6388857 |
| restore 写入字节 | 1367543808 | 1356341248 |
| 最后记录的 L1 保留字节合计 | 402555979 | 766391889 |

保留字节是逻辑缓存指标，不是额外物理内存或 PSS。save 不是唯一对象数；
计数版耗时不参与性能比较。容量变化消除了逐出，但没有消除并行任务之间
增加的页面保存和恢复写入，支持继续调查任务局部性及页面复用。

本地留存于 `build/shared-parallel/hot-cache-control/` 和
`build/shared-parallel/hot-cache-timing/`。各自的 audit.json 记录输入、实际配置、
计数及结果；后者 cleanup-audit.json 记录输入未变、三次卸载成功和无所属残留。
