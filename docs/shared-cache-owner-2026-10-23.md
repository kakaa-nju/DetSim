# 两层缓存共用不可变 owner 实验（2026-10-23）

候选确实让新写入的 StateStore hot cache 与共享池缓存共用一个不可变 vector，
但本轮没有稳定的 12-worker 提速，单次整体 PSS 差异也很小。保留为私有实验，
不向产品加入这版缓存查询接口，不宣称改善了并行扩展性。

## 改动与验证

候选增加 `SharedObjectPool::cached_blob(key)`：持锁检查失败状态后只查 Blob
缓存，不读盘、不调整 LRU；空结果不表示磁盘上没有对象。StateStore 在发布成功
之后，仅为没有 existing owner 且符合 hot-cache 预算的新写入查询它，命中则共用
owner，未命中按原路径复制。没有混入上一轮 pointer/memcmp 省略候选，也没有改变
发布接口、checksum、冲突比较或持久化格式。

所有四个依赖该头文件的编译单元（pool、StateStore、snapshot bundle、parallel）
均从一致的 full-FP 源码重编译；依赖文件经路径归一化核验，没有混入旧 pool 头。
产品源码和生产 tracer 未修改。

实际通过的验证：

- 基线/候选的共享 StateStore、共享快照集成测试，以及候选七项原生图/故障场景。
- owner 身份正反对照：基线为两个 owner，候选为同一个 owner；反转期望后，两版
  分别在预期断言失败。测试直接区分副本，未将“结果字节正确”当作命中证明。
- 源输入修改不影响已保存内容、相等/不等 reference hint、pool 切换、保留 owner、
  零 hot cache/冷只读回退，以及单个 65 MiB 对象超过 pool 容量后的原复制回退。
- cache-only 查询的冷 miss（含磁盘上已有对象）、Blob/Ready 隔离、只读/poison；
  16384+1 小对象证明查询不提升 LRU，淘汰不改变外部持有的 owner。
- 发布后注入 syncfs 失败：候选 save、后续读写和 shutdown 明确失败，独立只读
  pool 仍能验证已发布文件。文件可见不代表持久化成功。旧写入逻辑以同代新头文件
  重编译作反例，确实在“save 未发现刚注入的 pool 失败”断言处失败。

只读审查和专项测试草稿由 DeepSeek-V4.1-Flash / max 提供，主 agent 检查、编译、
执行并验收；辅助会话已归档。首次本机专项测试编译遇到冻结副本的原头文件相对
路径错误，保留失败日志后修正测试 include 路径，再运行上述对照。没有将编译失败
当作身份回归的预期失败。代码审查还指出两个缓存的逻辑预算仍会分别计数同一
buffer；不能将预算计数相加当作实际物理占用。

## 较大图计时

gpunode WSL，固定 NP3 Raft-library、pages/shared、BFS depth16、seed1、rounds100、
same-cpu、locality none。基线为已合入类型化缓存键的完整 O3 full-FP 构建
`ef808de53b2db36fcf644a2ac4e4ec9231a467702e8bc3f88f191cea95cc75c7`；候选为
`6c8a9828888f12c28dc83975b4a9f4ddc72303367d26d090c373bbfac376b912`。
两版各有自己的 native reference，计时两轮反转顺序；没有同时运行宿主采样器。

| --- | --- | --- | ---: | ---: |
| 1 | 156.7427 / 163.1078 | 148.9546 / 150.4568 | 159.9252 | 149.7057 |
| 12 | 20.1519 / 20.1408 | 20.1311 / 21.3496 | 20.1464 | 20.7403 |

单-worker 中位数低约 6.4%，12-worker 中位数高约 3.0%；后者一轮基本不变，

## 独立内存采样与决策

计时批次结束后，两版分别另跑一次 12-worker 大图，启用现有资源采样器。两次
同图检查及下载后重新摘要检查通过；各观察到 52 个进程、18 次 PSS 采样，进程
读取遗漏计数均为零。

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| 采样峰值 summed PSS（MiB） | 1132.02 | 1113.42 |
| 采样峰值 summed RSS（字节） | 1354911744 | 1331654656 |
| 普通采样次数 | 181 | 179 |

该对照 PSS 低约 1.64%，但只有一对样本，峰值是采样下界，PSS 也受共享页归属
影响；不能据此建立稳定的整体内存收益。RSS 会重复计算共享页，资源采样运行不
用于吞吐排名。局部消除副本已证实，整体收益不足以支撑本轮引入新 API。

源码、审查、构建摘要和测试命令/退出码在 `build/shared-parallel/shared-cache-owner/`；
计时、独立内存采样、逐图/输入核验与回收在
`build/shared-parallel/shared-cache-owner-wsl/`。两个批次均正常退出，六项 namespace
卸载成功，后验无本实验所属进程或宿主挂载残留，远端二进制/脚本摘要已核对。
下一步应继续缩小累计执行成本增加的来源，而不是把这项局部优化当作线性扩展。
