# WSL 独立搜索的 tmpfs 对照（2026-10-23）

将搜索目录放到 tmpfs，未改善本次独立搜索的并发吞吐倍率。这个实验用于继续
排查[独立搜索并发退化](independent-search-control-2026-10-23.md)，不是单张
状态图的协作探索加速比，也不是硬件扩展上限的证明。

## 方法和结果

沿用 gpunode WSL、固定 Raft-library fixture、NP3、pages/shared、BFS depth 12、
seed 1、rounds 100。每份搜索使用一个 worker，整个进程树绑定一个 guest CPU；
12 份搜索之间不共享 frontier 或 object pool。使用相同的 worker-cycle 诊断二进制
`6d771e15a7cce79dd830abb82dfe054f9303ba5403d0cd4316474fda3956d8af`，
不是最新产品二进制。仅改变各任务工作目录的文件系统，目标及插件摘要保持一致。

每配置两次，执行顺序为 disk1、tmpfs1、tmpfs12、disk12、tmpfs1、disk1、
disk12、tmpfs12；组间串行。搜索前屏障对齐开始，搜索结束后另设屏障，避免某份
任务提前进行 Python 图验证而干扰其他搜索。时间为最早命令开始至最晚命令结束，
不含启动前缀、图验证、关闭与 tmpfs 镜像导出。

| 文件系统 | 任务数 | 两次命令耗时（秒） | 均值（秒） | 独立吞吐倍率 |
| --- | ---: | --- | ---: | ---: |
| ext4 | 1 | 26.5822 / 24.5506 | 25.5664 | 1 |
| ext4 | 12 | 36.3635 / 35.9820 | 36.1728 | 8.48× |
| tmpfs | 1 | 23.6064 / 24.2543 | 23.9303 | 1 |
| tmpfs | 12 | 34.5772 / 35.8304 | 35.2038 | 8.16× |

倍率按 `12 × 单任务均值 / 12任务均值` 计算。tmpfs 降低了部分绝对耗时，但
单任务改善更大，倍率没有改善。样本少且存在波动，不能宣称文件系统永远无关；
tmpfs 仍有内核、页缓存/内存访问及文件元数据操作，也没有消除宿主调度影响。

52 份成功搜索全部通过 10457 节点、18266 边、18266 尝试边、零重试检查；
下载后重新计算的完整规范图摘要均为
`56ccf7cc9b866e62f6da715136eb596719b3f2b101915e93e4cf0c630217717b`。
native 参考检查节点与首次发现父边，完整图一致性另行比较，不把它扩大为独立的
全边串行 oracle。

## 全链路成本与回收

tmpfs 容量限制为 4 GiB；所有组最低 MemAvailable 约 5.48 GiB，未观察到 swap
增长。为保留证据，在验证、关闭之后将全部产物导出到 ext4：单任务复制约
1.47 秒，12 任务复制为 18.34 / 19.45 秒；第一次导出 sync 另耗
0.20–0.24 / 0.80–0.92 秒。这些均不计入上表，故不能据上表宣称保留全部落盘
镜像的端到端性能收益。写入导出元数据后还有一次 sync，未单独计时。

所有临时挂载位于独立 mount namespace；未调整宿主 ASLR、sysctl 或持久挂载。
监控器显式转发 SIGINT/SIGTERM；实际向监控器发送 SIGTERM 的回归返回 130，
子调用与挂载完成回收。它不是任意强杀、卡住的复制或同步都能有界清理的证明。
八组成功实验加一次中断实验共 32 项卸载全部成功；最终检查没有可识别的所属
进程、宿主挂载或 tmpfs 挂载点残留。失败/中断实验不计入 52 份成功搜索。

原始结果、下载图、分析脚本及清理核验位于
`build/shared-parallel/tmpfs-control-wsl/`，其中 `comparison.json` 保存输入摘要、
逐组时间与汇总，`post-run-verification.json` 保存远端脚本摘要及卸载记录。
DeepSeek-V4.1-Flash / max 辅助静态复核脚本，主 agent 执行全部 CPU 实验和验收；
辅助会话完成后已归档。没有修改产品代码，因此本次未重跑产品编译或组件测试。
