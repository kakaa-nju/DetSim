# 共享只读对象映射原型（2026-10-24）

已实现私有原型，让共享池的原始对象由只读文件映射承载，避免每个 worker 都保留
一份解压后的堆副本。当前仍在验证，未合入产品，尚无全链路性能收益结论。

## 实现边界

`ImmutableBytes` 统一只读 data/size/iterator 接口，内部持有堆 vector 或只读
MAP_SHARED 映射。映射检查常规文件、长度及 payload 边界；最后一个所有者释放
时解除映射，关闭 fd 或 unlink 路径不破坏已持有的字节。没有改写 vector 内部
布局或替换全局分配器。

共享池沿用 version1 的 codec0/codec1 格式及原有 kind/key/size/checksum 检查。
原型可发布 codec0 原始对象并映射其 payload；旧 codec1 对象仍验证并解压到堆。
新对象发布后，生产者 L1 在原有容量条件内复用已发布所有者；并发发布失败者
保留规范路径对应的对象，不缓存未发布临时文件的映射。

StateStore、快照视图、resident page 及捕获/恢复只读所有者已迁移。Packed 压缩
输入改为 span，编码逻辑不变；完整 bundle/copy-out 显式复制到可修改 vector。
VFS 使用临时复制适配，保留原有 FileContent 接口与归档格式，暂不计算 VFS 的
映射收益。私有 C++ 所有权类型发生变化，所有 tracer 翻译单元重新编译；实际
Raft 插件只用未变化的 C ABI，依赖记录和 api/plugin.h 已核对。

不改变目标进程、模型状态字段、归档字节或哈希语义。映射仍依赖现有“私有池
已发布文件在使用期不被外部修改”的契约；不宣称能容忍外部 truncate。缓存额度
仍是逻辑字节，不是 RSS/PSS 保证。原始文件可能增加磁盘和 page cache 占用，
这些必须随性能一起测量，不能只报减少复制。

## 已收集的验证证据

- 字节所有者检查及 ASan/UBSan：输入复制隔离、边界、只读保护、move、fd/path
  关闭后的持有及最后所有者解除映射。
- 对象池三种模式均通过现有并发发布、冲突、类型/哈希损坏、淘汰、保留 owner、
  只读、文件系统屏障和 poison 检查：压缩堆、原始堆、原始映射。
- 跨进程冷读取：原始旧实现写压缩对象→新映射读取器的解压路径；新原始对象→
  旧实现读取器；新映射对象在 pool 关闭/unlink 后仍由 held owner 正确持有。
- NP3 共享 StateStore、共享 snapshot/Ready/证明/故障注入集成检查通过。故障
  fixture 改成显式 mutable 副本，没有让只读对象可写或移除负例断言。
- NP2 packed/mapped × normal/tiny 四组完整字节 oracle 通过，含分支恢复、内存/
  socket 更新等原有检查。mapped tiny 显式冷重开池、关闭 L1 缓存，确认新映射
  地址不同但字节相同，并验证重新注册后的模型身份不变；packed 仍要求原磁盘
  读取证据。映射路径没有冒用只统计 packed IO 的 disk_reads 指标。
- 映射 tracer 的七项原生探索、存储、worker 丢失、重试、启动截止时间、取消和
  违规重放检查通过；真实 Raft depth12 为 10457 节点、18266 边、零重试，完整
  规范图摘要与冻结基线一致。串行参考仍只独立验证节点/首父边覆盖。
  两个控制版本也各通过了同一组七项原生检查。

初次编译发现完整 bundle 导出需要显式字节复制，已修复。测试适配还曾把 backing
检查放在 poison 后、用 packed IO 计数要求映射路径，以及在 generation 切换后
直接套用未重新注册的保存次数基准；修正了测试边界并保留失败日志，没有放宽
字节、身份或正常保存次数断言。这些不是性能收益证据。

## 后续对照

准备三个同接口版本：压缩堆、原始堆、原始映射；后两者隔离取消压缩与真正共享
解码字节的影响，再与原 typed-pool 基线比较完整探索。生产者 owner 复用同样
存在于三个控制版本，因此不能将其差异误归为 mmap。
必须核对实际映射使用、磁盘/PSS、完整图、缓存失败/淘汰及 1/12/24-worker 搜索
耗时，再决定是否采用。当前没有宣称减少了全部私有内存或已提高加速比。
