# 宿主亲和性窗口：计算与真实搜索对照（2026-10-24）

结论：限制到每个宿主物理核的一条逻辑处理器，明显改善了算术控制，但本轮
Raft-library自动搜索只快约1.9%。尚未证明稳定的搜索收益，不作为默认宿主配置。
不能把计算控制的收益外推到模型检验，也尚未取得近线性搜索加速比。

## 有界窗口与恢复

只读确认vmmem初始为PID21304、固定创建时间、mask ffffff，50个线程均为
processor group0/mask ffffff。重新查询Windows物理核分组后，选择555555，
即12个物理核各选一条LP。没有改变guest CPU编号或模型检查器实现。

窗口由独立SYSTEM计划任务完整拥有apply→sleep→restore。使用打开的进程句柄
与创建时间绑定写入，验证预期mask和系统范围，以及线程mask一致性。每次新目录、
nonce和目标世代进入所有标记。55秒只是sleep参数，实际修改窗口包括读回和记录；
保留QPC时间戳，不宣称它精确等于或严格不超过55秒。

控制器finally独立执行Stop精确任务→等待同创建时间的守卫进程退出→恢复目标
原mask并验证→删除任务。正常测量还要求applied与守卫restored都成立、没有
apply/restore错误，以及负载结束时仍在临时mask窗口中。controller-restored
不能单独证明正常试验成功。重启/世代变化、线程枚举失败、恢复失败均拒绝继续。

自建PowerShell进程的正常与强制停止测试通过。强制停止时实际观察到mask仍为1，
控制器随后恢复ffffff。错误创建时间、预期mask不符、越界mask均被拒绝；实际
Set后故障注入验证了回滚分支。当前V3两个测试直接对应最终构件，V2两个为历史
验证；全部都独立核对了nonce、世代、任务注销、守卫与目标退出。复核后的构件
没有剩余阻断，controller集成随后在下面两次真实窗口中接受验证。

这些保证不覆盖守卫和controller同时被强杀、机器崩溃或恢复系统调用自身失败。
线程一致性检查是非原子枚举快照。没有向真实vmmem注入异常；真实窗口都正常完成。

性能值仅取native parallel receipt的seconds，排除构建、确定性前缀、CLI/driver

相对两侧均值下降1.93%，单组不足以证明稳定收益；没有改变默认配置。

控制器记录了负载结束后的临时mask检查与尚未恢复的标记，其QPC早于restore
开始。最终同一PID/创建时间恢复ffffff，守卫退出、任务不存在，九项namespace
卸载成功，没有本轮Linux进程残留，Windows脚本摘要与启动清单一致。

## 产物与后续

代码、审查、自建进程测试及两次窗口的原始结果保存在
`build/shared-parallel/vm-affinity-control/`。计算trial为
`503c4115ebe2444fa8da8a3811c130b9`，搜索trial为
`df6792fb042649439b3490b9918dce47`，各有独立audit。

下一步应在真实搜索的绑定窗口中核对宿主LP运行分布，确认该约束对搜索负载的
实际作用，再调查内存/缓存或执行路径成本。算术有收益而搜索基本持平，说明
当前证据不足以把宿主计算资源分配当作搜索扩展损失的充分解释。
